# 测试协议

## 要回答的问题

在固定场景生成和固定后处理负载下，把后处理从独显转交给核显，是否能在包含跨适配器开销后稳定提高吞吐和尾部帧时间？

## 主要指标

- 平均 FPS：由稳态完成间隔计算；
- 1% low：最慢 1% 完成间隔的平均值换算成 FPS；
- P50/P95/P99 完成间隔；
- GPU 完成节奏 P50/P95/P99，以及包含流水线填充/排空的阶段 wall FPS；
- 独显场景阶段和后处理阶段的 GPU 时间；
- 核显后处理 GPU 时间；
- ABBA/BAAB 配对胜负与首尾基线漂移。

首帧没有前一完成时间，不参与吞吐统计。预热帧不写入正式结果。

## 默认顺序

每个阶段都先预热再测量。三组顺序为：

1. `single, heterogeneous, heterogeneous, single`；
2. `heterogeneous, single, single, heterogeneous`；
3. `single, heterogeneous, heterogeneous, single`。

这种顺序用于抵消线性升温、Boost 变化和阶段先后造成的偏差。正式比较取各模式阶段指标的中位数，同时检查每个相邻配对。

## 有效性门槛

- 两个适配器必须是不同的硬件 LUID，且均成功创建 D3D11 硬件设备；
- 跨适配器共享纹理和 keyed mutex 必须成功；
- 所有阶段完成规定帧数，GPU 时间戳不得 disjoint；
- 任一阶段超时、设备移除或共享失败，本轮直接无效；
- 同模式首尾平均 FPS 漂移超过 5%，本轮只保留原始数据，不下收益结论。

## 候选收益门槛

只有同时满足以下条件才输出“候选收益，需在游戏/引擎原型复验”：

- 异构模式中位平均 FPS 相对单卡至少 `+2%`；
- 异构模式中位 1% low 相对单卡至少 `+1%`；
- 至少 2/3 的局部 AB 配对中，异构模式平均 FPS 不下降；
- 异构模式 GPU 完成间隔 P99 不得恶化超过 5%；
- 基线漂移不超过 5%。

否则输出“未证明收益”。占用率上升、核显开始工作或单个阶段偶然领先，都不算性能提升证据。

## 后续游戏验证

台架通过只说明显式多适配器值得继续研发。下一阶段必须在可修改的开源游戏或自有引擎插件中复验，并保持相同画质、分辨率、镜头、着色器与帧数。不要对带反作弊的商业游戏做 DLL 注入式验证。
