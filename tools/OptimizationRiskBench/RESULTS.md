## 工作集修剪

256 MiB 私有内存 修剪后重新逐页访问 中位耗时从 0.92 ms 变成 50.74 ms 多出六万五千多次缺页 修剪完再用是有实打实代价的

## CPU 耗时识别

前台一个算完就 Sleep(1) 的帧样循环 加一个无关的持续计算线程 RenderLane.TryIdentify 八次全把无关线程当成关键线程 同核争用时把它提到最高优先级 帧样循环四秒里一个完整周期都没跑完 分到两个核上就没这个现象 p50 15.47 对 15.40 ms

## 纯策略

VerifyHold(45W, 41W, 98%, 96%) 为 true BoostPriorityTarget 饱和无 lane 回 Normal 有 lane 回 High CacheWarm.NvmeBlocks(true, true) 为 true

## 第二轮 音频 缓存 档案

- 音频低延迟 直接调生产的 Activate 和 Restore 44100 Hz 默认 448 帧 10.16 ms 开了变 128 帧 2.90 ms 关了回 448 机制是真的生效
- 缓存预热 前台 4 KiB 随机读 后台预读 512 MiB 文件 开关四臂 IOPS 16893 到 18698 p99 78 到 83.5 μs 和基线波动重叠 分不出好坏
- 交接台架 Repeat 3 跑两次 138 条里各失败 2 条和 1 条 日志里是档案替换的 IOException 保存失败会让交接 epoch 失效 这是保护路径在起作用
- 档案锁实验 持只读句柄时保存失败 原文件完好 释放后同一实例还是拒绝 新实例能存

## 之后改了什么

- 缓存预热整个退役 旧偏好启动时清掉 旧档案覆盖键加载时丢掉
- CPU 耗时候选提优改成默认关的手动实验项 CPU 饱和时游戏回普通优先级并取消候选
- 工作集修剪要可用内存低于 4 GiB 且低于总量八分之一才动
- 档案替换对 Win32 错误 32 33 1175 做四次退避重试 25 50 100 200 ms 重试耗尽保留旧档
- 改名 强制入口 单项覆盖 批量入库这些不再发布未保存的状态
- 受限 CPU 域改回 Normal 撤回候选线程晋升 功耗让路过滤无效采样 自动显卡分配按可见 EXE 和后代路径保护 共享显存查询改成单任务后台采样
