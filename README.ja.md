## 性能

上のグラフの測定条件は、i7-9750H のノート PC で WeChat・Clash・QQ・音楽プレーヤーをバックグラウンドに常駐させ、クリーンな状態を 100 とした相対値です。3 シナリオの平均で、Pavise なしが 59、通常モード 60、競技モード 96、極限モード 99 となりました。

Pavise は性能を新たに生み出すものではなく、バックグラウンドに取られていた分をゲームに戻すツールです。そのため、常駐プログラムが多く CPU やディスクの奪い合いが起きている環境ほど効果が大きく、もともとクリーンな環境や完全に GPU 律速のゲームでは変化は限定的です。

なお極限モードは高負荷シナリオで 71 にとどまり、競技モードの 93 を下回っています。抑制の強さと性能は比例しないため、既定のプリセットは最も穏やかな設定になっています。

実際の効果は、同じゲームの同じ場面でオン・オフを比較して確認してください。

## 使い方

ゲームの EXE またはショートカットを対象ライブラリに追加します。Steam / Epic / GOG / Ubisoft / Riot / WeGame / Battle.net / Xbox にインストール済みのゲームは、スキャン機能でまとめて取り込めます。

ゲームの実行中は自動的に保護され、デスクトップへの切り替えや最小化でも解除されません。ランチャー経由で起動するゲーム（リーグ・オブ・レジェンドなど）は初回の確認後に本体を記憶し、以降は直接認識します。ランチャー・アップデータ・クラッシュレポータ・アンチチートのプロセスがゲームとして認識されることはありません。

ゲーム終了後、記録に従ってすべての変更を復元します。Pavise 自体が異常終了した場合は、次回起動時に復元を継続します。

## モード

| モード | 抑制範囲 |
|---|---|
| 通常 | ウィンドウを持たないバックグラウンドを軽度に抑制し、リソースを取り続けるものは強めに。使用中のプログラムには触れない |
| 競技 | ゲーム以外をすべて抑制。ウィンドウを持つものも対象。現在の前面プログラムとその子プロセスのみ除外 |
| 極限 | 競技に加え、共有サービスホストもバックグラウンドコアへ移動 |
| カスタム | バックグラウンド抑制・ネットワーク・通知などを項目ごとに選択 |

いずれのモードでも、アンチチート、実行中のゲームのホストプロセス、Windows のコアサービス、ゲーム用アクセラレータ、他のログインアカウントは抑制されません。この境界はどの設定でも変更できません。

## 機能

**プロセスとコア**

- ゲームプロセスに高い優先度、ディスク IO と GPU スケジューリングの優先度、および専用コアを割り当て。バックグラウンドはモードに応じて降格または他のコアへ移動
- CPU 分割はハイブリッド構成・X3D・複数プロセッサグループに対応。6 コア以下ではコア分割を行わない
- コア割り当てはコア単位の手動指定に対応。全コア・ハイパースレッディング解除・P コアのみ・反転のプリセットがあり、変更は「適用」を押して確定します。多くの場合は触る必要がありません。スケジューラは既定でゲームのスレッドを P コアに置きます
- 高負荷バックグラウンドのコア収縮：すでに抑制されたバックグラウンドを全コアから少数の物理コアへ寄せます。狙いは並行メモリアクセスによる帯域の圧迫で、優先度でも効率モードでも届かない部分です。寄せ先はあなたがゲームに割り当てたコアから実時間で算出し、マルチ CCD ではゲーム側の L3 を丸ごと避けます。ベンチ実測で 33 fps から 95 fps
- スマートフレーム保護：フレームレートを決定しているスレッドを特定して個別に引き上げ。CPU 飽和時のベンチで 1% Low が 77%〜96% 改善
- 予備ブースト：カーネルアンチチートにハンドルを拒否されるゲームでは、プロセス生成時にシステム側から高優先度を与えます。次回起動から有効
- サービス誘導：対局中、指定したサービスプロセスをバックグラウンドのコアへ誘導します。停止はしません

**グラフィックス**

- バックグラウンド GPU 譲り：バックグラウンドプロセスが GPU を使用している場合、その GPU スケジューリング優先度も併せて低下
- NVIDIA 詳細調整：電源最高パフォーマンス、DLSS4 Transformer 上書き、ゲーム単位の ReBAR 有効化、Ansel インジェクション無効化、バッテリー時のフレーム制限解除。元の値はスナップショットを保持し、無効化時に復元
- デュアル GPU 機では、抑制されたバックグラウンドのうち dGPU を使うものを iGPU 側へ移します

**入力デバイスと割り込み**

- フィルターキー・固定キー・切り替えキーを解除。Microsoft の定義は短い打鍵を無視する機能であり、有効な状態は遅延の追加にあたります
- マウス・キーボードのシステムによるサスペンドを禁止。しばらく放置した後の最初の操作がぼやける症状に効きます。対象は入力デバイスのみで、USB メモリやオーディオ機器には触れません
- 他のツールが変更した入力キュー長を修復。ポインタ精度を高める設定（システムのマウス加速カーブ）の解除にも対応
- 4K/8K マウスによる割り込みストームをゲームのコアから引き離す。有効化の前に代償を提示します。1000 Hz 以下ではほぼ効果がありません
- ディスクコントローラの読み取り完了割り込みを空いているコアへ移動

**メモリと電源**

- 対局前の低優先度スタンバイページの解放、対局が安定した後のバックグラウンドワーキングセットの回収、スタンバイリストが閾値を超えた際の消去。三項目とも既定はオフで、それぞれの代償をスイッチの下に明記しています
- 対局中は電源プランを「究極のパフォーマンス」へ切り替え。本機に無ければ自動作成し、あればそれを使用します
- 電源プラン、ネットワーク、Game DVR、通知、インデックスサービスはゲーム終了後にすべて復元

**目に見える部分**

- 診断ページ：本機の能力を読み取り専用で確認し、各結論に根拠のレベルを明記。NVIDIA への書き込みが実際に反映されたかの実測、マウスのポーリングレート実測、GPU が現在電力壁・温度壁の制限を受けているかの表示に対応。割り込みの行はカーネル ETW で DPC と ISR を追跡し、主要因を名指しします
- セッションレポート：プレイ時間、抑制したプロセス数とその CPU 使用量、電力壁・温度壁による制限を受けていた時間の割合
- ゲームライブラリは強制引き受けに対応。エミュレータやクラウドゲームなど検出できないものは、プロセスが起動した時点で対局として扱います
- ホワイトリストは独立したページ。ドラッグして追加するだけで、適用範囲は自動的に判定

完全にローカルで動作するツールです。サービスのインストール、データのアップロード、ゲームプロセスへのインジェクション、ゲームのメモリやファイルの変更は一切行いません。書き込みは可能な限り読み戻して照合し、期待値が読めない場合は成功として扱いません。

## 実装しないもの

出回っている入力遅延向けのレジストリ設定は、その多くが 0.1 ミリ秒単位に作用するもので、遅延の主要因はレンダリングキューにあります。この種の項目について Pavise は報告のみを行い、変更はしません。Bluetooth マウスと 125 Hz のポーリングレートがこれに該当します。診断ページが指摘するだけで、変更するかどうかはあなたが決めます。

MSI モード、低遅延モード、バックグラウンドのフレーム制限、ウィンドウ表示ゲームの最適化、ゲームファイルのプリウォーム、位置による CPU 0/1 の除外は、いずれも実装した上で削除しました。理由はそれぞれ、実測で効果が確認できなかったこと、デバイスが起動不能になる書き込みのリスクがあること、そして意味の取り違えです。ドライバのバックグラウンドフレーム制限は実際にはフォーカスを失ったアプリケーションに作用するため、ゲームから切り替えた際に制限されるのはゲーム自身になります。削除した項目は、旧バージョンが書き込んだ値をアップグレード時に自動で復元します。

メモリ解放についても同様です。スタンバイリスト全体の消去で増える空きメモリは 382 MB にとどまる一方、18.9 GB のファイルキャッシュを破棄することになり、ゲームのロードでディスクから読み直しが発生します。そのため既定では、システムが再使用の可能性が最も低いと判定したページのみを対象とし、所要時間は 13 ミリ秒です。

## ビルド

Windows に同梱されている .NET Framework コンパイラを使用します。Visual Studio は不要で、復元が必要なパッケージもありません。

```cmd
build.cmd      rem Pavise.exe を生成
dev.cmd        rem 旧インスタンス終了 → ビルド → 起動
```

ソースからのビルドにはデジタル署名がないため、SmartScreen の警告が表示されます。

## 実行とデータの保存先

`Pavise.exe` をダブルクリックするとトレイに常駐します。他プロセスの調整には管理者権限が必要です。自動起動はタスクスケジューラで実現しています。起動時に GitHub へバージョンを一度確認しますが、本機のデータは送信しません。

データは既定で `%AppData%\Pavise` に保存され、対象設定・ホワイトリスト・実行ログが含まれます。UI と機能のスイッチはレジストリの `HKCU\Software\Pavise` に保存されます。実行ファイルの隣に空ファイル `Pavise.portable` を置くと、保存先がプログラムのディレクトリに切り替わります。

設定ページにワンクリックの復元機能があります。
