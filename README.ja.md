# Aegis

ゲームとバックグラウンドの資源境界を整理する小さな Windows ツール

`C#` · `WinForms` · `単一実行ファイル` · `中文 / English / 日本語`

</div>

## 先に結論：本当に性能は上がる？

Aegis は性能を魔法のように増やすものではなく、CPU や GPU を本来の上限より速くするツールでもありません。

役割はもっと単純です。**ゲーム中に、バックグラウンドアプリ、更新処理、アンチチートのユーザーモードプロセスなどに奪われている資源を、できるだけゲームへ戻します。** CPU 時間、ストレージ IO、スケジューリングではゲームを優先し、使っていないバックグラウンドプログラムには少し控えてもらいます。ゲーム終了後は、変更前の状態への復元を試みます。

バックグラウンドで多くのプログラムが動き、CPU やディスクの競合が起きやすい PC では、カクつき、フレーム時間、1% Low が改善し、その結果として平均 FPS も少し良くなる可能性があります。もともとシステムが軽い場合や、ゲームが完全に GPU 上限へ達している場合、差は通常わずかです。設定を強くしすぎると、ゲーム、ボイスチャット、アンチチートとの互換性を悪化させることもあります——競技モードは既定で最も強い段階なので、選ぶこと自体がそのトレードオフを受け入れる意味になります。

一言でまとめると、**Aegis は新しい性能を作るのではなく、PC がもともと持っている性能をゲーム中に邪魔されにくくするツールです。** 効果は同じゲーム、同じ場面でオンとオフを比較して確認してください。

## このツールの役割

Aegis はユーザーが明示的に追加した EXE または LNK を起点に対象プロセスを認識します——ゲームに限りません。保護や提優をしたい任意のプロセスを追加できます。そのプロセスが動いている限り Aegis はそれを認識し続けます。表示ウィンドウや前面状態は必須ではないため、デスクトップや他のアプリへ alt-tab しても保護から外れません。

一部のプログラム（特に自己解凍型ランチャー）は、実際に長時間動く本体をインストール先の外、たとえば一時フォルダーで実行します。Aegis は入口実行ファイルの基本名に、よくある位番/バージョン接尾辞（`xxx64` や `xxx_x64` など）が続く場合、それも同じ対象として認識できます——指定したディレクトリ内にとどまることを必須としません。

最初はゲーム終了後も資源を使い続けるプロセスを整理するために作りました。その後、対象検出、CPU 分離、アンチチート制御、異常終了時の復元、UI を少しずつ追加しています。現在もローカルで動くツールであり、サービスやフレーム収集器をインストールせず、実行データを送信しません。

自動調度は対象プロセスへの注入、メモリの編集、ファイルの変更を行いません。優先度、IO、ページ優先度、CPU Sets、ハード affinity は API が対応する場合に読戻します。Power Throttling には信頼できるプロセス単位の読戻し API がないため書き込み結果だけで判定します。League 専用欄のファイル操作は個別確認が必要な可逆隔離だけです。付加層を記録付きで移動し元の位置へ復元でき、復元不能な削除は提供しません。性能差はゲーム内ベンチマークや普段使っている監視ツールで確認してください。

## 動作の流れ

プロセス名だけで保護を開始することはありません。選択した入口、インストールルート内のプロセス関係、位番/バージョン接尾辞による補完照合、表示ウィンドウ、前面状態、描画向けの配置を組み合わせて判定します。アンチチート、更新、クラッシュ報告、外部プラットフォームの役割は、ユーザーが明示的に選んだ場合でも対象から除外します。一度確認したセッションはフォーカスの変化をまたいで保護され続け、デスクトップへ切り替えただけで「対象が終了した」と誤認されることはありません。

確認後の処理は現在のプリセットで変わります。

- **標準**は現在のセッションでユーザー向けウィンドウを持たないプロセスに軽い Eco 方針を適用し、継続高負荷だけを強化します。前面ウィンドウと使用中のプログラムは引き続き例外扱いです。
- **競技**は初回からもっとも厳しい CPU と優先度の境界を作ります——前面 / 表示ウィンドウも自動除外されません。ゲーム一式、アンチチート、許可リスト、他のユーザーセッション、本当の Windows 中核サービスは固定の安全境界として残ります。
- **カスタム**はバックグラウンド制御、サービス停止、ネットワーク、通知、リフレッシュレートを個別に選べます。加えて、プリセットを切り替えずに競技モード相当の抑制範囲と電源強度だけを採用するかどうかも、独立したスイッチとして選べます。

選択した対象プロセスには高優先度、高い IO 優先度、GPU 調度優先度、CPU に合った CPU Sets を適用できます。バックグラウンド側は優先度を下げるか別のコアへ移します。読戻しに対応する項目では書き込み失敗や読戻し不一致を成功として表示しません。

アンチチートプロセス、進行中の対戦のセッションホスト（中国版クライアントなど）、それらのインストールディレクトリは、どの抑制強度でも無条件に例外です——この境界はプリセットやスイッチで変わりません。抑制が原因で対戦が切断されることを防ぎます。

復元記録には PID、作成時刻、イメージ名、読み取れる元の調度値、元の CPU Sets を保存します。元の Power Throttling 状態は信頼できる方法で読めないため、復元時は完全復元を主張せず方針制御を Windows に返します。Aegis が異常終了した場合は次回起動時に残っている復元記録から処理を続けます。

## 主な機能

- EXE と LNK を使う対象ライブラリ、ドラッグ操作とローカルスキャンに対応——ゲームに限定されません
- 常駐ランチャーが保護モードを保持しない、対象プロセスのヒューリスティック選択
- 位番/バージョン接尾辞による補完照合——自己解凍型ランチャーの本体がインストール先の外にあっても認識
- フォーカスに依存しない保護——確認済みセッションは前面を失っても最小化されても保護と提優を維持
- CPU メーカーに依存しない CPU Sets。ハイブリッド CPU は OS が報告する効率クラスで分離し SMT をすべて保持。同構成の 6 コア以下は強制分離せず、8 コア以上だけが規模に応じて少数のバックグラウンドコアを確保
- 継続的に異常な DPC や割り込みがある物理コアを競技配置から除外
- Windows が対応する項目で API の戻り値と実際の読戻しを使う提優と抑制
- League of Legends 専用欄に WeGame 経由起動、LCU 準備完了判定、検証済みパスだけの整理、対戦中の完全ヘッドレス化、独立した復元監視を用意
- ベンダー別アンチチート制御。初期状態では比較的保守的な ACE のみ有効
- 電源計画、ネットワーク節流、MMCSS、Game DVR、通知、一部サービスの復元
- 自動セッションと分離された明示的な HAGS と VBS の永続設定
- セッション時間と確認済み調度結果を保存するローカルレポート
- 中国語、英語、日本語の実行中切替

## 安全境界

アンチチートプロセス、進行中の対戦のセッションホストとそのインストールディレクトリ、Windows 中核サービス（セッション確立、認証、サービス管理、コンポジター、オーディオ処理など）、他のログインセッション、Aegis 自身は、どのプリセット・強度でも抑制対象にしません——この境界は設定で変わりません。

競技級の強度でなければ、Aegis は前面プロセス、表示中のメインウィンドウを持つアプリと同名プロセスおよび子孫を通常のバックグラウンド対象にしません。ブラウザや IDE などで UI プロセスだけが保護される状態を避けます。追加の例外はユーザーが管理する許可リストから設定します。競技級の強度（競技モード、またはカスタムモードで個別に有効化）は前面 / ウィンドウの例外を外します。ゲーム一式、アンチチート、許可リスト、他のユーザーセッション、Windows 中核サービスは固定の安全境界として残ります。

アンチチート抑制自体は強い方針です。保護されたプログラムがハンドルを拒否したり状態をすぐ書き戻したりする場合があります。その結果は失敗として記録し、表示のために成功扱いすることはありません。

ログオフやシャットダウン時には、再起動しても自動的には消えない変更（電源プラン、レジストリ系スイッチ）を復元します。終了時はリスク順に処理し、まずプロセス状態（優先度、affinity、EcoQoS、コア分割）を復元してから、時間のかかるサービスと表示設定を戻します。終了予算が尽きた場合に残るのは、再起動でも自力で戻らない側です。

## League of Legends 専用欄

WeGame に通常の認証と起動を任せ、LCU のログイン成功と current-summoner エンドポイントの応答を確認してから、検証済みパスにある WeGame と任意コンポーネントだけを終了します。対戦開始後はクライアント標準の LCU エンドポイントでロビー UX を閉じ、独立した監視プロセスが対戦終了後にローカル資格情報を再取得してロビーを復元します。手動復元を選ぶと、そのセッションではヘッドレス化を再実行しません。

設定ページにあった Cross の永久削除は廃止しました。`Cross` も他の付加層と同じ可逆隔離を通るため、復元できない削除経路は残っていません。

可逆隔離は Cross、DiagnosticAssistant、FeedBack、NetworkAssist、TQM、TenioDL を同一ボリュームの隠し保管庫へ移します。先に記録を書き、削除や上書きを行わず、League または WeGame の実行中は拒否し、復元競合時も既存内容を保持します。更新で部品が再取得され復元が上書きできない場合は、全項目が元の位置にあることを確認したうえで記録を破棄し、再び隔離できます。

実行時処理はプロセス注入、メモリ編集、ゲーム中核ファイルの変更を行いません。`League of Legends.exe`、Riot の中核・認証・パッチ処理、ACE は対象外です。LCU 資格情報は短時間だけメモリに保持し、ログ、レジストリ、ファイル、子プロセス引数へ残しません。ゲームディレクトリが変わるのは、個別確認した可逆隔離だけです。専用機能が無効ならディスク走査もプロセス列挙もクライアント接続も行わず、WeGame はログインユーザーとして起動するためゲームとアンチチートが巻き添えで昇格しません。

## HAGS と VBS

HAGS スイッチはシステムの GPU 調度設定を変更し、再起動後に反映されます。変更前の値を先に保存します。

VBS スイッチは DeviceGuard 関連のレジストリ値と `hypervisorlaunchtype` を変更します。こちらも再起動が必要です。無効化するとメモリ整合性、WSL2、Docker、Hyper-V、Windows Sandbox に影響するため、ユーザーが用途に合わせて判断する必要があります。

この二つは自動セッションとは別の永続設定です。復元に失敗した場合はスナップショットを残します。

## ビルド

Windows に含まれる .NET Framework C# コンパイラを使います。復元するパッケージはなく、Visual Studio も必要ありません。

```cmd
build.cmd
```

スクリプトはアイコンを生成し、管理者権限マニフェスト、製品情報、ファイル版 `1.5.0.0` 付きの `Aegis.exe` をビルドします。

ソースからのビルドは初期状態では Authenticode 署名されません。個人のオープンソースプロジェクトは未署名でも配布できます。発行者の本人性を確認し SmartScreen の警告体験を改善したい場合は、自分の信頼されたコード署名証明書を使用できます。

## 実行とデータ保存先

- `Aegis.exe` を起動すると通知領域に常駐します
- 他のプロセスやシステム設定の変更には管理者権限が必要です
- 設定のメンテナンス欄に一括復元があります
- 自動起動はタスクスケジューラを使います
- 起動後に GitHub の版確認を一度行い、PC のデータは送信しません

既定のデータディレクトリは `%AppData%\Aegis` です。

- `Aegis.profiles.dat` は対象設定を保存します
- `Aegis.whitelist.txt` はユーザー除外を保存します
- `Aegis.reports.log` はセッションレポートを保存します
- `Aegis.log` は実行ログを保存します
- `HKCU\Software\Aegis` は画面と機能設定を保存します

実行ファイルの隣に空の `Aegis.portable` を置き、その場所に書き込める場合は同じディレクトリへデータを保存します。

## ソース構成

- `src/Core` は対象検出、調度、抑制、復元
- `src/Platform` は Windows API、設定、パス、サービス制御
- `src/Ui` は WinForms 画面と自描画コントロール
- `src/Tests` は内蔵セルフテスト
- `scripts` はアプリケーションのスモークテスト

実装では `SetPriorityClass`、`SetProcessDefaultCpuSets`、`NtSetInformationProcess`、`SetProcessInformation`、`D3DKMTSetProcessSchedulingPriorityClass` などの Windows API を使います。PID が再利用されたときに別のプロセスを復元しないよう、作成時刻も識別情報に含めます。

## 検証範囲

内蔵セルフテストは現在 `63` 件です。CPU 構成とコア数別の方針、CPU Sets とハード affinity の復元、PID 再利用、実子プロセスの提優、段階的抑制、位番/バージョン補完照合の境界、フォーカスに依存しないセッション保護、前面とユーザーウィンドウの保護、イベント駆動スキャンの予算制御、セッション境界、League 資格情報の解析、厳密な終了対象境界、可逆隔離の往復と競合保護、セッションレポート、配布メタデータ、オフスクリーン UI 描画を扱います。環境に必要な機能がない場合は `PASS` ではなく `SKIP` と記録します。

同一コア競合テストは二つの計算プロセスを意図的に一つのコアへ置き、競合側を停止します。CPU 時間を解放すると throughput が戻ることだけを示し、実ゲームの FPS や 1% Low の証明ではありません。

HAGS、VBS、電源プラン、MMCSS、ネットワーク節流、サービス停止、実際のアンチチート製品との互換性には現在エンドツーエンド自動テストがありません。対象環境で個別確認が必要です。
