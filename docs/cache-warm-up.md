# 缓存预热恢复

入口是「优化策略 → 会话附加 → 缓存预热」，也可在游戏库的「独立配置 → 内存与电源」里设置逐游戏开关。默认关闭，所有模式均尊重用户设置，没有任何模式会强制开启。

重新实现后的设置键为 `GmCacheWarmV2`，不继承已经退役的 `GmCacheWarm` 旧值。全局是默认值，游戏自己的开关优先；保存失败不视为成功开启。当前策略目录从 33 项增加为 34 项。

## 运行规则

- 已确认的对局稳定 90 秒后，在后台线程上读取本游戏目录的资源包。只读文件，不加载 EXE/DLL、不编译着色器、不注入游戏、不读写游戏进程内存。
- 必须能确认交流供电且未启用节电模式；可用物理内存至少 4 GiB，且不低于总内存的四分之一。
- 总读取预算取三者中的最小值：2 GiB、总内存的十六分之一、超出 4 GiB 可用内存部分的一半。每个资源包最多读前 256 MiB，每 1 MiB 后等待至少 32 ms，约不超过 31 MiB/s。并不承诺 Windows 会保留全部已读页面。
- 只接受系统能确认没有寻道惩罚的本地固定磁盘；机械盘、网络盘、无法查询的磁盘跳过。这次恢复不包含旧版「极限档强制开启」逻辑，用户显式开启时 SATA SSD 与 NVMe 均可参与。
- 限定游戏安装范围，跳过目录联接、符号链接、脱机文件，以及已列出的反作弊/日志等目录。只选择指定资源包扩展名，优先使用最近访问时间排序；该时间可能未被系统及时更新，不代表已准确预测下一张地图的资源。
- 开启待机内存清理时，预热让位。关闭开关、关闭守护、换局、退局、紧急恢复或内存/电源条件不再满足时停止。每块读取前重新检查条件，已经提交的磁盘读取允许收尾；关闭排空超时会报告失败。
- 同一会话、安装目录和渲染程序路径至多进行一轮资源读取，不循环扫描预读；读取中因内存不足停止也不会重置预算反复读。等待阶段被取消后可重新等待，修改开关或安装路径变化也会重新计时。退出只释放本功能的线程和文件句柄，已进入系统缓存的页面由 Windows 回收，不主动清空缓存。
- 使用独立且整局稳定的会话编号；首次游戏提优完成后清零的耗时计数不参与预热准入。同一游戏的新对局更新编号并使旧回调失效。
- 同一档案学习到新的安装目录或渲染程序路径时取消旧路径任务，重新等待 90 秒；仅 PID 交接或路径大小写变化不重启任务。

## 验证

使用临时设置与自建资源文件验证：读取预算、节流间隔、取消、文件占用、文件内容不变、路径范围检查、逐游戏覆盖、旧键隔离、待机清理互斥、换局/退出/恢复边界及保存失败。测试不启动游戏，不运行 Pavise 的调优循环，也不显示测试窗口。

2026-09-08 初次恢复验证：开发构建成功，完整隔离回归 71 组全部通过，中英文卡片离屏绘制检查通过。本机只读检测确认能识别固态盘、交流供电及内存余量。初次报告位于 `build/cachewarm/regression.txt`。

同日后续十轮复核修复了首次提优计时清零、安装路径交接与等待取消的边界，最终开发构建成功，完整隔离回归 **75/75 组通过**。[十轮复核报告](reviews/2026-09-08-handheld-fixes-review.md)，原始结果位于 `build/review10-regression-results.txt`。两次验证均未进行真实游戏资源预热或游戏性能对比。

这项功能可能帮助后续资源读取，尤其是重复访问。它不是着色器编译预热，也不保证平均 FPS 或 1% low 提升；预读内容不命中后续需求时，额外 I/O 可能没有收益。
