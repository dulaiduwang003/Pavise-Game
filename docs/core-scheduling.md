# 手动核心调度：实现与验收

核心调度是独立的调优导航入口，**一页**：一张游戏选核图，下方一个「游戏独占这些核」开关。重压后台绑核已移除。独占使用系统调度范围和游戏准入；保存方案、运行中确认、恢复未完成分别显示状态。此功能与中断观测独立。

2026-09-09 起原「核心分配」「核心隔离」两个子 Tab 合并。独占范围不再由用户单独选择，改为从游戏选核推导：`CoreScheduling.ExclusiveMaskFor` 只把所选核对齐到整颗物理核；若独占之外剩不下两颗完整物理核则返回 0，界面据此停用开关并说明原因，同时把 `IsolationOn` 归为关，避免留下一个开着却为空的范围。合并的理由是这两步本来就是同一件事：文档此前也要求隔离范围必须与游戏选核有交集，否则收走的核没有进程能用。

## 用户交互

- 全局入口：核心调度（单页）；逐游戏入口：游戏配置 → 核心。优化策略页保留「核心控制」「预设细节」「会话附加」三个 Tab。
- UI 沿用项目原有 ROG 编号卡片、切角边框、滑动开关和按钮，选核高亮跟随当前档位的主题色。
- 游戏选核图固定显示，不再切换编辑角色。CCD、全选、清空、反选只响应用户点击。
- 「关超线程」只在已选物理核中各保留一个已选逻辑线程，不扩大到其他 CCD，不修改系统 SMT 设置。
- 页面自上而下是游戏选核图、独占开关卡片、状态与保存。开关卡片按当前选核显示推导出的独占范围，或说明为什么推不出来。关闭独占不改变游戏选核。
- 游戏按逻辑 CPU 选择；独占范围由它推导，按整颗物理核对齐并联动 SMT。**唯一的硬性限制是独占之外至少保留两颗完整物理核**，CPU 0 所在物理核是否独占交给用户决定。
- 默认选核是全选，此时独占会占满全部物理核、一颗都不留给系统，开关会停用。选核区提供「留出系统核」快捷键，从末尾的整核开始让，让到刚好成立为止；说明文字同时给出总核数、已选核数和还需让出的颗数。
- 逐游戏跟随全局时显示全局方案，取消跟随后恢复未保存的手动草稿。独占始终由全局管理，逐游戏页只读显示，不给开关，避免看起来能按游戏设置；逐游戏改选核也不会改动独占范围。主题、语言或缩放导致界面重建时保留编辑草稿。
- 逐游戏编辑器在界面重建后恢复草稿时，自身配置版本未变则刷新全局隔离引用与摘要，保留游戏选核和跟随选择，可继续保存逐游戏方案。仅更新继承的隔离不会产生未保存标记；自身配置冲突、全局读取失败或拓扑过期仍会阻止该引用更新。
- 不支持独占的平台在独占开关卡片中直接说明系统要求；已有开启配置仍允许关闭。
- 页面底部「保存核心方案」一次保存游戏选核与独占的整份方案，共用校验、未保存状态和重新读取操作。存储写失败、拓扑变更或其他编辑器已修改原方案时不提交旧草稿。
- 当前对局冻结游戏和隔离方案；对局中保存的新方案从下一次入场生效。下方状态每秒刷新，显示本局隔离是否已经确认及其实际范围。
- 游戏提优关闭时不执行游戏选核和核心隔离，界面显示原因。

例如：把游戏放在 CCD 0 上，勾选「游戏独占这些核」，保存核心方案。独占范围即这些物理核，普通后台默认避开，可用范围仍包括 CCD 1。

## 旧配置兼容

沿用设置键 `GmManualCorePlanV1`，新记录格式为 `2|拓扑|游戏掩码|隔离开关|隔离掩码`。旧 V1 记录读取时保留游戏与隔离字段，丢弃重压字段；旧重压落点即使为空、冲突或超出当前拓扑，也不会阻止有效游戏与隔离方案迁移。损坏记录仍拒绝执行并保留原文。

旧重压开关和落点从策略清单、逐游戏配置入口和运行时热度采样中移除，所有模式都不再执行。保存逐游戏方案时清除旧覆盖字段。已有后台压制收据的恢复路径保留；普通后台不再接受新绑核，反作弊原有独立亲和性策略保留。

## 核心隔离运行时

要求 64 位 Windows 10 2004 或更新版本，且只有一个处理器组。实际写入时还会检查完整拓扑、管理员调度权限、已有系统分配以及读回结果；条件不满足时拒绝启用。

隔离范围通过 `NtSetSystemInformation(SystemAllowedCpuSetsInformation = 168)` 设置系统默认允许的 CPU 范围，输入是每组一个 64 位逻辑 CPU 掩码。当前识别的游戏渲染进程通过 `ProcessAllowedCpuSetsInformation = 67` 获得所选隔离核的准入。保留游戏原先的允许集合，并使用精确硬亲和性限制实际游戏落点。CPU Set ID 不作为位编号，不使用 `0x100 + CPU` 的猜测映射。

信息类 168 和 67 是未公开接口，不属于微软承诺稳定的 Win32 API。版本门槛不代表所有较新构建均已实测；每次启用均重新核对结果，不匹配时撤回本次改动。

写入后必须同时满足：系统 CPU Set 的 `Allocated` 标记与目标隔离范围完全一致；目标进程的允许集合与写入值完全一致；面向目标进程查询的 `AllocatedToTargetProcess` 标记与其允许的隔离范围一致。单凭 API 成功返回不会显示生效。后续每隔约 0.5 秒核对系统与进程状态，每 2 秒核对主程序与守护进程之间的连接。

游戏硬亲和性写入后，每轮巡检读回一次。读不出来的轮次不计数。读得出且与所选范围不符，说明游戏自身或其他进程调整了它，处置由核心调度页的「检测到其他进程调整亲和性 立即纠正」决定：关闭（默认）时保留其改动，本局不再落核，改动后的掩码若不再覆盖独占范围则撤回独占；开启时每秒用首次写入前留存的句柄读一次，不符即恢复原值再写回所选范围，不设次数上限，首次记一条日志，退局报本局纠正总数。只有 Pavise 自己的写入连续三次读回未生效才算失守：掩码仍覆盖独占范围则停止写入并保留独占，不覆盖则撤回独占。

普通进程默认避开隔离区，但这不是系统安全边界：内核中断、DPC、具有特殊权限或系统例外的任务仍可能占用。因此界面不承诺隔离核绝对 0% 占用。没有为游戏设置实时优先级，也没有修改中断分配、停用音频或更新服务、写入 `ReservedCpuSets` 注册表项。

## 退出和故障恢复

独立的隐藏守护进程持有机器范围互斥锁、恢复句柄和持久化收据。主进程通过标准输入输出发送有限命令；守护进程不启动正常托盘、调优扫描或游戏识别。

1. 写入任何进程准入前，先持久化启动标识、PID、创建时间、原允许集合和计划写入集合。
2. 完成准入后重新检查系统范围，再持久化「准备写入系统」阶段，最后设置系统范围并读回。准入阶段失败不会撤销另一个工具刚写入的系统范围。
3. 正常离场、关闭提优或退出时，先恢复系统默认范围，再恢复各进程原允许集合和原硬亲和性。
4. 主进程退出、输入管道关闭，或 15 秒未收到主进程消息时，守护进程恢复隔离。守护进程异常退出时，主进程根据收据恢复；两者均退出时，下次启动及卸载/重置恢复入口继续处理。
5. 恢复时校验 PID 与创建时间；进程已退出或 PID 已复用时不修改新进程。句柄暂时打不开、身份不确定或读回失败时保留收据。
6. 收据包含系统启动标识；跨重启只清理旧收据，不向新启动的系统或复用的 PID 写旧掩码。
7. 已有其他 CPU 分配时拒绝启用。运行中检测到外部范围或进程准入被修改时停止生效声明，恢复只写回仍与本程序目标值一致的状态。未确认恢复时保留收据并显示错误，不报告已恢复。原生接口没有跨工具的原子比较交换能力，不能保证与另一款同时写相同系统设置的软件协调。

## 游戏选核

手动游戏选核使用精确进程亲和性并读回。写入前保留带身份绑定的恢复句柄和原亲和性，不扩大进程已有的受限范围。被保护或拒绝写入的游戏按原有边界跳过。软 CPU Set 成功不作为手动落核成功的证明。

手动亲和性和中断观测的临时亲和性具有不同恢复归属。关闭观测或降级为系统观测，只撤回观测的临时绑定；隔离系统范围、游戏准入和手动亲和性继续生效。

## 验收与复现

2026-09-09（当日第三次改动）：放开 CPU 0 所在物理核的独占限制。原 `Validate` 里的 `schedule.error.cpu0` 规则来自隔离功能引入时的保守选择（旧 `ReservedCoresTweak` 注释写作「CPU0 是系统和多数驱动的默认落点」），代码与文档均无实测依据。真正防止系统没核可用的是「独占之外留两颗完整物理核」那条，予以保留；CPU 0 交由用户决定。CPU Sets 是软层，把 CPU 0 移出系统允许集合不会赶走硬绑定其上的中断与线程，且隔离不跨重启，最坏情况重启即恢复。同时补上「留出系统核」快捷键，解决默认全选下开关必然停用的问题。

2026-09-09（当日第二次改动）：两个子页合并为一页，独占范围改为从游戏选核推导。原双子页的跨页草稿、两条保存路径和跳转入口相关回归已按单页结构改写，`CorePlanSplitPageDraft` 更名为 `CorePlanMergedPageDraft`；界面布局回归改为断言「选核图在上、独占开关居中、保存在下」的纵向次序。全量隔离回归 75/75 通过。

2026-09-09（当日第一次改动）：核心调度独立入口与双子页。

## 接口依据

- [Microsoft CPU Sets](https://learn.microsoft.com/en-us/windows/win32/procthread/cpu-sets)：CPU Set 的分配标记、访问限制与硬亲和性的关系。
- [Pavel Yosifovich 的 CPU Set 示例](https://github.com/zodiacon/WindowsInternals/blob/master/CpuSet/CpuSet.cpp)：系统允许集合接口的组掩码调用形式。
- [NtDoc Process Information Classes](https://ntdoc.m417z.com/processinfoclass)：进程允许集合信息类与调度权限。

另外通过本机 `ntoskrnl.exe` 与微软公开符号核对 19045 的信息类 168 输入形式及分配标记来源，并用上述实机进程验证完成行为闭环。生产代码不依赖符号、内核地址、驱动注入或内核补丁。
