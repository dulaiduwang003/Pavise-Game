# 微软后台治理实验

## 目的与实现

验证已核实的微软后台对象能否在运行期间接受资源限制，并在结束后恢复原值。当前内置名单、可信路径、服务宿主和家族身份判断位于 [WindowsBackgroundPolicy.cs](../../src/PaviseApp/WindowsBackgroundPolicy.cs)，档位参数位于 [WindowsBackgroundLimits.cs](../../src/PaviseApp/WindowsBackgroundLimits.cs)。

当前正常档设置每个目标 5% CPU 配额、最多两个后台物理核心；激进档设置 2%、最多一个后台物理核心，并进一步降低优先级。实际核心范围还要与目标原范围和既有核心隔离求交，不能扩大原范围。名单涵盖诊断、搜索索引及小组件，不表示每次实验都会运行全部名单对象。

## 原生实验方法

2026-11-10 的本机实验使用 Windows x64、12 个逻辑处理器，纳入 10 个已运行系统后台对象及一个自有 CPU 校准进程：

| 类别 | 对象数 |
| --- | ---: |
| 已核实的诊断服务宿主 | 2 |
| 搜索索引主进程 | 1 |
| 索引工作子进程 | 6 |
| 小组件服务 | 1 |
| 自有配额校准进程 | 1 |

步骤如下：

1. 保存 PID、创建时间、路径、原优先级、亲和性、I/O 优先级及 CPU Sets；核实服务与家族归属。
2. 采集约 5 秒基线，建立限额 Job，关联已确认目标，再分别读回 Job 和进程状态。
3. 限制期间采集约 10 秒，检查 Job 成员、核心范围和 CPU 配额。校准进程使用 1% 配额，用于核对计量单位；这不是正式产品的正常档或激进档。
4. 清除本方 Job 限制，恢复保存值，采集约 5 秒；独立监护再次核对原值。

## 结果

11 个对象均完成应用与读回，没有失败对象；11 个对象均完成恢复，独立监护核对通过。[数据汇总](data/windows-background-20261110.csv)列出类别、配额、成员状态与恢复结果。

自有校准进程的整机 CPU 占比依次为 8.3343%、1.0001%、8.3380%。基线及恢复阶段约占一个逻辑处理器，限制阶段与设置的 1% 配额一致。系统后台在该次采样中大多低占用，因此其纳管结果依据 Job／进程读回，不能从低 CPU 占用本身推导配额效果。

这次记录验证了所测对象的纳管及恢复。正式实现另外通过自有工作进程验证配额与守护恢复，不为测试而终止系统服务。共享宿主包含名单外服务、身份不明或受到系统保护时，仍须遵守生产准入条件。

## 公开检查

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/Test-BackgroundGovernanceRuntime.ps1
```

该公开入口验证治理状态及恢复方法，并仅对测试进程自身进行原生提优往返；它不修改真实系统服务，也不重放上面的服务实验。完整隔离说明见[测试说明](../../tests/README.md)。
