# Pavise 全屏缩放

这是内置的自研窗口捕获、GPU 缩放和呈现组件，不依赖 Magpie，也没有复制它的源代码。当前首版提供等比放大、黑边和可选锐化；它不是 Magpie 全功能复刻，也不包含插帧、DLSS 或 FSR 2/3。

## 使用

1. 在游戏库对应卡片打开「全屏缩放」，并开启 Pavise 守护。
2. 在游戏内选择较低分辨率的窗口模式，例如在 1920×1080 显示器上使用 1280×720。Pavise 不自动修改游戏的分辨率或画质设置。
3. 游戏窗口处于前台且收到有效画面后，缩放输出覆盖其所在显示器。卡片显示加载、运行、暂停或错误状态。
4. 切换到其他窗口时暂停，返回游戏后恢复。关闭开关、关闭守护或游戏退出时停止。`Ctrl+Alt+U` 停止本次缩放；需要继续时关闭再打开卡片开关。

「锐化」默认开启，使用带邻域限幅的轻量锐化。「窗口鼠标映射」默认关闭：关闭时保留游戏自己的鼠标输入，适用于使用原始输入并自行限制光标的 3D 游戏；开启时将输出窗口收到的普通鼠标消息按画面比例映射回源窗口。使用原始输入的游戏可能忽略映射后的消息，此时应关闭映射。当前尚未实现完整的光标虚拟化，游戏菜单和自由光标操作需要逐游戏验证。

## 实现与退出

- Windows Graphics Capture 捕获指定游戏窗口，D3D11 在 GPU 上复制客户区，丢弃积压的旧帧后执行双线性放大和可选锐化，再通过 flip-model 交换链呈现。生产路径不把画面读回 CPU。
- 原生组件嵌入 Pavise 主程序，首次使用时解包到 `%LocalAppData%\Pavise\Scaling\<SHA256>\Pavise.ScaleHost.exe`。启动前校验内容哈希，并持有防写文件句柄直到启动完成。
- 每次只运行一个缩放组件，绑定游戏和 Pavise 的进程 ID、创建时间与窗口归属。组件被精确豁免于 Pavise 的后台压制。
- 关闭开关时通知组件退出；超时结束该组件。原生端另外监视父进程和游戏句柄，在父程序异常退出、游戏退出或窗口销毁后自行收尾。捕获会话、帧、GPU 对象、事件和进程句柄随退出释放；已校验的组件文件保留作下次启动缓存。
- 不注入游戏 DLL、不读取或改写游戏内存、不拦截游戏渲染 API、不改显卡驱动配置。使用系统捕获接口并不意味着所有游戏或反作弊产品都保证兼容；受保护或禁止捕获的窗口可能无法使用。

## 当前范围

面向 Windows 10 2004 及以上的 64 位系统、D3D11 显卡与 SDR 输出。独占全屏不是目标输入，完整 HDR 管线、完整光标虚拟化和多显示器兼容矩阵尚未验证。窗口尺寸改变时重建捕获池，失去前台焦点时关闭捕获并隐藏输出，避免持续处理后台画面。

缩放会额外消耗 GPU，并可能增加延迟。只有降低游戏分辨率节省的成本高于捕获和缩放开销时才可能获得净收益；CPU 瓶颈场景不能因此承诺提帧。尚未进行实际游戏的 FPS、1% low、输入延迟或画质对比，不应把链路测试当作游戏性能验证。

## 构建与验证

开发构建和保护构建都将原生组件作为资源嵌入主程序。构建需要 MSVC C++ 工具，或者可移植 Zig（可通过 `PAVISE_ZIG_PATH` 指定 `zig.exe`）；构建脚本不会自动下载安装软件。原生输入文件与构建脚本的哈希用于增量构建校验。

```powershell
.\build.cmd -b dev build\Pavise.scaling-dev.exe
.\tools\Test-Scaling.ps1
# 可选：捕获已经打开的 ChatGPT/Codex 窗口，输出窗口始终隐藏。
.\tools\Test-Scaling.ps1 -Integration
.\build.cmd -b dev build\Pavise.scaling-selftest.exe --selftest
```

普通原生测试使用合成图案检查硬件 / WARP 着色器像素、黑边和隐藏呈现。集成测试使用临时设置，验证嵌入组件解包、真实窗口捕获、加载状态、进程身份保护、开关停止与重启、会话结束，以及父进程退出后的组件清理；不启动游戏，不保存捕获画面。测试文本输出位于 `build/scaling/`。只有显式设置 `PAVISE_SCALING_SHOTS` 时才保存离屏绘制的游戏卡片 PNG，内容不包含捕获窗口。

2026-09-08 验证结果：开发构建成功；上述硬件 / WARP 与隐藏集成测试通过；完整隔离回归 70 组全部通过；中英文卡片在 330、520、720 宽度下离屏绘制并检查布局。尚未运行保护发布构建，也未完成实际游戏的前台显示、输入和性能验收。
