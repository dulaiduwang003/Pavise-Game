# Pavise 使用教程

对应版本 2.2.0.0。配图为界面实拍，深色主题、无光标。

[线上教程](https://ycnqux4mseky.feishu.cn/wiki/Do1jwytjmit0DJke8CvcyJEenxd)

## 01｜三分钟上手

以管理员身份运行 Pavise，程序进入托盘。调整其它进程的优先级需要管理员权限，普通权限下大部分功能会置灰。

系统需要 Windows 10 2004（内部版本 19041）或更高。更早的系统上后台压制依赖的能效模式和逐进程计时器精度隔离不存在，程序会提示后退出，并把此前版本留下的系统改动还原掉。

四步就能开始用：

1. 进游戏库添加游戏，或用扫描导入已安装的平台游戏
2. 模式保持默认的智能档，核心保持全核
3. 打开概览页的守护开关
4. 进一局真实对局，退出后回来看概览的最近一局和日志

概览页左侧是主导航，右上角显示当前模式与对局电源计划。守护关闭时不做任何事，打开后检测到游戏才接管。

![概览：守护开关、当前模式、最近一局与主导航](../screenshots/overview.png)

界面支持浅色主题，在设置页切换。

![浅色主题下的概览页](../screenshots/overview-light.png)

## 02｜模式与顶部工具条

右上角的模式菜单默认有四档。先用智能，遇到具体问题再往上调。

| 模式 | 什么时候用 |
|---|---|
| 智能 | 默认。日常游戏，兼顾切屏多任务 |
| 电竞 | 需要把资源尽量集中给游戏时。压制范围扩到游戏之外全体 |
| 极限 | 以电竞为底，自动开启本机所有通过资格检查的可选优化项。默认隐藏，在设置页解锁并重启电脑后才出现在菜单里；压制范围与力度和电竞完全相同 |
| 掌机 | 掌机和轻薄本。压制范围同电竞，功耗侧交给厂商工具 |
| 自定义 | 想逐项决定的用户 |

![模式菜单：非自定义档会锁定并标注它接管的开关](../screenshots/mode.png)

顶部还有两个入口。对局电源计划选择使用哪套电源方案，默认是 Pavise 托管的“由软件调度”方案；也可以改选本机任意计划，Pavise 只负责切换，不改它的参数。

![对局电源计划选择](../screenshots/power.png)

功能搜索用来直接定位设置项，不用记它在哪一页。

![功能搜索：输入关键词定位到具体开关](../screenshots/search-hit.png)

## 03｜游戏库

添加游戏的 EXE 或快捷方式，也可以扫描导入 Steam、Epic、GOG、育碧、Riot、WeGame、战网、Xbox 的已安装游戏。

通过启动器启动的游戏（如英雄联盟）首次确认后会记住游戏本体，之后直接识别。启动器、更新器、崩溃上报和反作弊进程不会被认作游戏。

![游戏库：路径、渲染观测标签、家族后台开关与条目操作](../screenshots/library.png)

### 渲染标签与家族后台压制

每个条目会显示渲染观测状态。「已观测渲染」表示在这个 EXE 上看到过 GPU 3D 活动，「暂未确认」表示还没有记录。

家族后台压制默认关闭，这是对的。关闭时，游戏平台、启动器外壳、游戏目录下的常驻进程和游戏派生的子进程整族放行。打开后这些关联进程会按普通后台压制，可能导致平台聊天、浮层或依赖功能异常。

建议顺序：先打一局，核对渲染标签确实指向游戏本体，再决定要不要开。需要保留的具体进程可以单独加白名单。

## 04｜逐游戏独立配置

选中游戏后点独立配置，或直接双击卡片。每个游戏可以单独覆盖 34 项策略，没覆盖的跟随全局。

![独立配置：运行模式与后台压制覆盖](../screenshots/gameconfig.png)

四个分组各管一块：

![独立配置—核心：可以把某套核心选择锁定给这个游戏](../screenshots/gameconfig-core.png)

![独立配置—系统环境](../screenshots/gameconfig-env.png)

![独立配置—显卡](../screenshots/gameconfig-gpu.png)

大部分覆盖在对局激活时确定，下一局生效。暂停非必要服务和禁止 CPU 空闲是当前会话内处理的，关掉即撤销。一套覆盖可以一键清回全局。

## 05｜优化策略

高级 → 优化策略，分四个标签页。非自定义模式会锁定并标注它接管的开关，右上角显示当前实际生效的行为。

![核心控制：后台压制、提优、GPU 降级与守门项](../screenshots/policy.png)

四个标签页的分工：

- **核心控制**：后台压制总开关、后台 GPU 优先级降级、重压后台绑核（实验性）、游戏进程提优、渲染线程单独提优，以及显存驻留
- **核心分配**：CPU 分区。先保持全核，需要时再按本机拓扑调整。手动选核要点右下角的应用才保存
- **预设细节**：后台范围、下载、录制、多媒体调度
- **会话附加**：Windows Update、自动维护、无线扫描、息屏、进入游戏切英文、待机内存清理、禁止 CPU 空闲、缓存预热、厂商性能档

带开启确认的功能全部默认关闭。建议一次只开一项，在同一场景下对照评估。

## 06｜显卡

按硬件实际支持选，不要全开。不支持的项会自动置灰。

![显卡页：通用、NVIDIA、AMD、Intel 四个标签](../screenshots/graphics.png)

- **通用**：应用显卡偏好，给后台程序保存 Windows 节能显卡偏好，下次启动生效。同页的自动后台节能显卡默认关闭，开启后会在对局稳定约一分钟时检测一次，把仍在游戏渲染卡上跑 3D 的后台程序自动登记
- **NVIDIA**：电源最高性能、低延迟模式、Smooth Motion 插帧、着色器缓存放开、DLSS 覆写、逐游戏 ReBAR。原值有快照，关闭即恢复
- **AMD**：Anti-Lag、AFMF 补帧、RSR 超分
- **Intel**：全局低延迟，仅在驱动报告支持实时切换的 DX9/DX11 路径上启用

显卡功耗墙在对局中拉到厂商允许的上限，退局按快照还原。

## 07｜系统环境

这一页放的是需要重启、或者会留在机器上的改动。每一项都可还原，但开之前先读风险说明。

![系统环境：内核调度、设备链路、键鼠链路三组](../screenshots/environment.png)

- **内核调度**：HAGS、AMD Smart Access Memory、VBS、推测执行缓解卸载、游戏模式守护、窗口化优化、可变刷新率优化、计时器分辨率
- **设备链路**：设备电源管理、网卡链路节能关闭、网卡中断合并实验
- **键鼠链路**：辅助功能键、HID 电源、输入队列长度修复、指针精度增强

网卡中断合并默认保持驱动原值。显式开启实验时只暂存公网 IPv4 探测路由命中的唯一物理有线出口的标准 Off 值，重启生效，非游戏时段同样承担更高的中断率；Adaptive/Medium 属厂商私有值，程序不会猜测，恢复时必须同时匹配 NetCfg GUID 与 PnP 实例。VBS 关闭前有独立的风险确认。

## 08｜白名单

拖入 EXE 即可，作用范围自动判断。白名单里的程序在任何模式下都不会被压制。

按实际依赖来配，不要把整个目录都加进去。输入法、外设工具、录屏软件、需要保留功能的平台进程是典型候选。

## 10｜设备中断

先观测，再调整。这一页的所有判断都建立在实测数据上，没有数据时不要动。

![设备中断页](../screenshots/interrupt.png)

### 使用说明

挪核是持久改动：写入注册表、重启生效、每台设备留有备份收据、随时可全部还原。整个流程只有一个入口需要你做判断——选哪台设备、挪去哪些核。下面把每一步说透。

#### 第一步：开启对局观测

页面顶部打开"对局观测"。它用内核 ETW 采集每台设备的 DPC 活动，按局记账，需要管理员权限。

**观测本身会掉帧，开着它打的每一局都在付这个代价。** 说清楚代价从哪来：

- 内核把对局期间的每一条 DPC 事件都推进采样会话，Pavise 的消费线程在对局中实时处理这条事件流——事件越密（高帧率、设备中断多的机器）负担越重
- 会话另占 32MB 内核缓冲，对局结束即释放
- 具体掉多少帧没有台架数字，跟机器和游戏强相关；能确定的是方向：它只会让对局变差，不会变好

所以使用纪律是：**观测是诊断工具，不是常开功能。** 为了调整而开、攒够数据就关、验证完成后保持关闭。两个内置的止损别误解成"没开销"：

- 证据攒满后自动降为**四局抽一**采样——但被抽中的那一局仍是全程采样，代价不打折
- 开启前的确认弹窗会再提示一次帧率损耗，那不是客套话

然后正常打游戏。记账规则：

- 一局至少 **60 秒**才算合格局，闪退秒退不计
- 攒够 **3 个合格局**才出裁决，裁决取最近 **5 局**的实测

#### 第二步：读懂列表再挑设备

攒够局数后，列表按实测排序，与游戏核争用的设备排前面。先看标签：

- **[对局建议]**：多局实测达到建议门槛，值得处理的就是它们
- **[已生效] / [待重启] / [待验证] / [未收敛]**：钉核的生命周期状态，见第四步
- **[输入设备]**：键鼠链路。可以钉，但避免钉到低频小核——输入延迟比 DPC 冲突更伤
- **[环境页]**：网卡类设备由系统环境页统一管理，这页不重复接管
- **[驱动汇总]**：同驱动多设备的合并数据，定位不到单台实例，只供参考

单位参考：单次 DPC **≤100µs 正常**；**500µs** 约等于 144 FPS 下 7% 的帧预算；**≥1000µs** 可能直接丢帧。重点看"对局建议"标签配合最长耗时——偶发一次尖峰不值得动，多局稳定越线才值得。

三类设备页面会明确提示不建议碰，原因各不相同：

- **MSI-X / RSS 多消息设备**（现代网卡、NVMe）：中断本来就分散在多核并行处理，钉到少数核等于亲手拆掉并行度
- **StorPort 存储控制器**：完成 DPC 跟随发起 IO 的核跑，钉核写了也基本无效
- **显卡与音频**：显卡中断的既有策略是靠近渲染线程（渲染车道负责），钉离游戏核正好反着来；音频 DPC 挪到拥挤的小核上会跑得更慢，症状是劈啪声

#### 第三步：选择核心并写入

选中设备，点"选择核心"。弹出的对话框里：

- 默认建议的目标核就是**游戏核之外**的核心——把冲突设备挪开，不是挪近
- 可以顺带勾选**提升中断优先级**，让这台设备的 DPC 在目标核上优先执行
- 确认后写入注册表，同时落备份收据。**重启后才生效**

一次只动一台。改动多台再一起重启，出了问题分不清是谁的。

#### 第四步：重启并验证

重启后设备显示 **[待验证]**——此时只是"写进去了"，还不知道有没有用。打一局，观测会自动确认落点并给出实测：

- 变为 **[已生效]**：中断确实落在目标核上。再打两三局对比裁决数据，冲突消失才是真的成功
- 变为 **[未收敛]**：写入被驱动或系统忽略，落点没到目标核。先还原，再尝试列表里它的**上级主控**（有些设备的中断实际由父控制器路由）

#### 还原

- 底部"还原全部亲和性设置"按钮：按收据一键撤销本页写过的全部钉核，重启后回到原状
- 设置页的"清除全部配置"同样会还原这里的改动
- 收据独立于 Pavise 进程：异常退出不丢，下次启动接着认账

#### 什么时候该动，什么时候不该

值得动手的形状：帧率正常但**规律性卡顿**，观测里某台设备带着 [对局建议] 标签、最长 DPC 稳定在几百微秒以上、且不属于上面三类不建议碰的设备。

不值得动手的形状：没有 [对局建议] 标签、只有偶发尖峰、或卡顿源头在别处（先看会话报告和系统体检的中断行）。没有数据时不要动——这一页的第一原则。

## 常见问题

**开了没感觉到提升。** 先确认后台确实有东西在抢资源。系统本身干净、或者游戏完全卡在显卡上，Pavise 能还给游戏的就很少。在同一场景下开关对比，不要跨场景比。

**游戏平台的聊天或浮层出问题了。** 关掉那个游戏的家族后台压制，或者把具体进程加白名单。

**某个开关自己关掉了。** 驱动或系统拒绝了写入，回读核实没通过，程序按设计撤销并停止尝试。日志里有具体原因。重新打开开关等于重新授权尝试一次。

**中断页说没有数据。** 需要管理员权限，并且要打开对局中断观测后完整打几局。单局时长太短的不计入。

**改完要不要重启。** 系统环境页的项目需要重启，页面上会标注。其余都是对局期临时改动，退局自动还原。
