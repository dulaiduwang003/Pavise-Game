# v2.1.3.1 项目审查记录

日期：2026-08-28

## 范围与方法

审查覆盖程序启动与退出、会话识别和接管、后台进程保护、策略配置与逐游戏覆盖、电源和服务恢复、显卡及新增输入/内存功能、主要界面页面、配置保存/重置和版本发布入口。既有未提交功能保留，不借审查重写正常路径。

每个确认的缺陷先核对调用链，再用隔离场景复现修复前的失败；修复后重复定向回归，并由另一位审查者检查改动。除故障场景外，也检查原来正常的启用、关闭、取消、继承、再次进入游戏和正常恢复。

## 本轮处理的问题

| 范围 | 发现的问题 | 修复与回归重点 |
| --- | --- | --- |
| 会话恢复 | AMD、GPU 偏好预写入和部分策略的剩余恢复记录未触发重试；清账失败可能误报完成 | 恢复记录参加剩余状态判定，完成条件检查操作结果及记录；保留合法待命预写入 |
| CPU 空闲 | 写前准备记录被当成已完成修改，异常恢复可能覆盖外部值 | 区分准备、确认写入、恢复和结清；未确认写入不确权，已发出的不确定恢复不重复覆盖 |
| 电源计划 | 异常恢复忽略当前方案；切换已发出但读回失败时丢掉原值 | 核对当前方案归属；不明状态留账；再次尝试前先处理未完成恢复；本次运行中已恢复后只重试清账，不重复切换 |
| 服务与下载暂停 | 写前记录失败仍停止服务，回滚失败后可能丢掉恢复责任；旧准备记录可能被误认领 | 停止前验证记录；保留内存及持久恢复记录；仅确认归属的停止允许恢复 |
| 全部核心 | 手动全选仍继承全局限核，部分情况下应用按钮不可用 | 全选明确解除对应限制；部分选择、预设和跟随全局的原有行为继续回归 |
| 功耗让路 | 验证停止后无法关闭或经确认重试 | 已开启可关闭；新开启保留硬件、权限、确认和保存成功条件 |
| 显存保护 | 保存失败仍清除验证停止状态；取消确认可能显示错误状态 | 开启保存失败不改内存状态和验证停止状态；关闭仍保留即时尝试释放的行为 |
| 显卡开关 | 能力不可用时已有选项被隐藏或锁死 | 显示真实选择并允许关闭；仍阻止不支持的开启、档位和继承；保留 AMD API 可用性门槛 |
| 辅助键 | 部分修改成功后界面丢失恢复入口 | 以真实恢复记录显示状态，已有恢复责任仍可操作 |
| 异步界面 | 设置页或白名单的旧结果覆盖更新后的状态 | 校验代次和控件身份，合并刷新请求；自启变更不丢弃独立的缓存计数；检查正常刷新、关闭及重建 |

显卡改动的交叉复核还检查了正向能力缓存与 API 不可用同时出现的情况，并移除普通界面同步中新增加的功耗查询，避免为显示状态反复调用驱动。

### 实际改动

- 删除游戏启动约 30 秒后的一次性模块枚举及异步回调，不再为覆盖层识别申请读取游戏内存的权限；游戏识别和后台压制继续使用原有流程。

## 家族压制与 Steam 自动豁免冲突修正（本次窗口家族补齐之前的结果）

首次覆盖层用例验证了名单和恢复边界，但未把用户明确开启的家族压制与新增名单组合验证。随后确认：Steam 被无条件自动豁免，削弱了原开关及说明承诺的作用。本次新增 6 组组合回归，先复现旧行为，再接入修正。

### 处理规则

- 当前游戏的「压制家族后台」关闭时，保留 Steam 主程序、网页与覆盖层辅助进程的自动保护，避免默认家族算法不能覆盖同胞辅助进程而丢失保护。
- 开启时，该局 steam、steamwebhelper、gameoverlayui 不再获得新增名单的自动豁免，按原有后台规则处理。允许压制不等于强制压制，前台/可见窗口等既有规则仍按原模式生效。
- 游戏本体、候选、手动白名单、系统基础保护，以及其他受保护游戏已确认的同一进程，仍优先放行。不从共享启动器进一步扩散到所有同胞进程。
- OBS、Discord、RTSS 等独立录屏、通信、硬件与输入音频保护不随家族开关取消；未采用“只保留一个渲染进程”的做法。
- 继续复用原进程快照，不恢复游戏 DLL 扫描，不增加开关、不改持久白名单。开关提示与每次开启的确认同步说明 Steam 界面、聊天、覆盖层和依赖功能可能变慢或异常。

## 同游戏后台窗口豁免修正（当前结果）

按用户进一步澄清，本次范围是同一游戏的对局渲染目标与后台客户端，白名单继续除外，不取消 OBS 等独立工具的现有保护。

### 确认的缺口与处理

普通模式原先只从可见窗口集合中扣除已缓存的游戏家族、渲染器祖先和后代。当前快照中新出现的同游戏大厅窗口，以及其跨目录网页辅助进程，可能还不在缓存集合中，因此被窗口规则误豁免。同名窗口扩张也会触发相同遗漏。完整路径事件可能提前刷新检测，不能把这种遗漏一概描述为固定延迟 20 秒。

- 抽取实际生产过滤步骤 `FilterUserFacingGameFamily`，保留原四组扣除，再按当前档案的精确路径、已学习路径、安全根目录或已有家族证据补齐成员。
- 新增范围只使用当轮唯一 PID、相同登录会话、有效创建时间及规范路径和名称；父子链两端均需身份有效、创建顺序正确。重复 PID、未知创建时间、复用身份和跨会话关系不会作为新证据。
- 不把缓存 PID 或共享 Steam/WeGame 祖先重新作为扩张种子，不按客户端名称推断归属。
- 只移除可见窗口这一层豁免。名称、精确路径、应用家族三种白名单仍优先；对局渲染目标、待确认候选、其他受保护档案、独立工具与系统安全规则不变，普通模式的直接前台保护仍保留。
- 未修改通用渲染识别、Sticky、Boost 或退出恢复。原逻辑在首次判定失联时尝试释放后台压制，恢复失败由既有恢复队列重试；不能把发起恢复等同于立即恢复成功。
