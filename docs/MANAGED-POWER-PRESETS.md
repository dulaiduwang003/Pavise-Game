# 托管电源来源与适配边界

3.2.0.2 保留七份原始 `.pow` 资源，其中六份参与自动托管；卓越性能没有自动路由，不作通用回退。来源由内部按确认的架构、设备形态和智能/竞技场景选择，不提供手动来源入口。选定来源导入独立新 GUID 后，再保留本机日常偏好、电池基准和非对称缓存调度。来源的 CPU、I/O、空闲、自主控制、性能检查周期、历史及异构参数均保留在完整资源和数据模型中，不再使用旧的 66 项 AC 白名单拼接表。来源名称不是性能提升的证明。

## 场景与来源

| 条件 | 托管处理 |
| --- | --- |
| 自动选择 | 按确认的 CPU 架构、设备形态和智能/竞技路由，具体分支以 `ManagedPowerPreset.Architecture.cs` 为准 |
| 历史手选来源 | `PowerPlanSourceV1` 不再参与运行决策，启动时清理旧偏好；原有恢复记录继续有效 |
| 所有电池 DC | 回填原返回方案的全部可读 DC 基准，不把来源 AC 复制到 DC |
| 日常使用偏好 | 显示、睡眠、电源按键、合盖等 AC 参数回填本机原方案 |
| 对局期间变更 | 对局电源沿用原有锁定规则，来源没有独立选择入口 |
| 不切换或指定已有计划 | 原选择优先，不套用托管来源 |
| 掌机及其他移动端 CPU | 智能使用通用计划；普通同构 AMD 移动端竞技使用 AMD 低延迟；混合核心 AMD、解锁型移动端等继续使用通用计划，无设备识别开关或型号名单 |
| 线程撕裂者、至强、EPYC、Opteron、工作站、多处理器组或多插槽 | 智能与竞技均使用通用计划，保留本机日常 AC 偏好及全部 DC 基准，退局恢复原计划 |
| 类别无法确认、ARM、虚拟机 | 保留原方案，不套用其他品牌来源 |

顶部“策略设置”仅保留游戏场景和对局电源两项。对局电源保留由软件调度、不切换和指定已有计划；来源下拉框及来源描述均已移除。旧 `PowerPlanSourceV1` 即使尚未清理也不会生效；启动清理不会删除计划所有权及退局恢复记录。退出对局返回原计划。

## 保护边界

- 完整来源导入后回填屏幕超时、睡眠、休眠、电源按钮、合盖等本机日常 AC 偏好及全部 DC 基准。
- 来源的自主模式、`PerfCheck`、历史、空闲等项目按原始来源保留；平台是否实际支持或执行这些设置，不能仅凭写入值判断。
- 非对称缓存 X3D 保留本机停泊与异构调度保护，区别单 CCD X3D 与双 CCD 非对称缓存；不把模板中的全解停泊当成缓存 CCD 调度。
- 实验室 CPU 空闲策略在来源生效后覆盖；“跟随原策略”表示跟随当前来源基准。关闭/切换覆盖时恢复该来源原值，不能把全部来源一律恢复成同一个默认值。
- EPP 功耗让路仅在实际自主性能控制模式支持时执行；来源或空闲策略变化前先恢复 EPP，再重新采样，避免使用上一来源的基准判断新来源。
- 来源切换前先恢复实验室覆盖，再创建新 GUID；失败保留恢复记录，不覆盖其他会话或用户原有计划。
- 保留“不切换”、指定已有方案及退局恢复，不增加每秒全参数巡检和自动修复。旧 `HandheldDeviceMode` 不再参与运行决策。
- 掌机不再使用独立的本机高性能分支；按 CPU 与核心结构自动路由。工作站及多处理器平台统一使用通用来源，不再枚举或挑选本机已有高性能计划。“不切换”和指定已有计划继续优先。
- 旧托管数值表、旧架构调参类、旧隐式最佳性能 overlay 激活均已退役，不作隐藏回退；仅保留历史收据恢复。
- 日常 AC 与全部 DC 回填同时保留原注册表类型与内容，包括 REG_BINARY；本机无值时不合成零，清除目标副本对应覆盖。

实现中的完整来源与路由以 `ManagedPowerPreset.cs`、其数据/架构文件为准；导入、偏好回填及每次来源/模式独立 GUID 的生命周期见 `PowerPlan.Presets.cs`。AI 功能目录保留历史内部标识 `ManagedPower2223`，该标识不表示继续使用 2.2.2.3 模板；目录说明自动路由、历史手选失效、空闲后置覆盖及 EPP 适用条件，不再列出来源选择器。
