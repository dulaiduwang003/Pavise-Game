## 性能

上图是 v1.7.1 时期的四档台架测试。测试条件：i7-9750H 笔记本，后台运行微信、Clash、QQ、QQ 音乐，以干净系统为基准 100。三场景平均下来，不开 Pavise 为 59，常规模式 60，竞技模式 96。图里的常规和竞技就是现在的智能和专注，极限模式已下架。

Pavise 不产生额外性能，作用是把后台占用的那部分还给游戏。所以后台程序多、CPU 或磁盘争抢明显的机器提升明显，系统本身干净或者游戏完全卡在显卡上的，提升有限。

极限模式在高负载场景只有 71，低于竞技模式的 93，这就是它下架的原因。压制强度和性能不是正相关关系，默认预设是最温和的一档。

实际效果请在同一游戏、同一场景下自行开关对比。

## 候选技术：VidMm 显存驻留护盾

> 研究候选，尚未进入正式功能。以下内容描述的是准备先做独立台架验证的方向，不代表已经生效，也不承诺一定提升。

显存驻留护盾面向显存预算吃紧时的长帧。Pavise 计划通过 Windows 公开的 `D3DKMTQueryVideoMemoryInfo` 读取游戏在实际渲染显卡上的 `Budget`、`CurrentUsage`、`CurrentReservation` 和 `AvailableForReservation`；确认游戏持续接近预算并开始使用共享显存后，再用 `D3DKMTChangeVideoMemoryReservation` 为游戏声明一份保守的最低物理显存需求。

这不是增加显存，也不是把显存硬锁给游戏。Reservation 是 Windows 显存管理器判断进程最低工作集的提示，目标是在压力发生时减少游戏纹理和其它资源被迁出本地显存、再从系统内存调回造成的长帧，主要观察 1% / 0.1% low 和 P99 / P99.9 帧时间，显存充裕时不动作。

该方案使用系统已有的用户态 WDDM 接口，不安装驱动、不注入游戏、不修改游戏内存，不需要购买内核驱动签名。目标进程句柄被反作弊拒绝、渲染显卡无法唯一确认、游戏已有自己的非零显存 Reservation、核显统一内存或多 GPU 语义不清时都会直接跳过。

正式接入前先做独立台架和跨 NVIDIA / AMD 真机 AB。只有显存压力场景中多数配对的 1% low 至少提升 5%、P99 帧时间至少改善 8%、平均帧回退不超过 1%，并且切出游戏、游戏退出、Pavise 崩溃和显卡驱动重置后的原值恢复全部通过，才有资格成为可选功能；真实游戏不过线就否决，不因为接口能调用而上线。

## 使用

把游戏的 EXE 或快捷方式加入目标库，也可以用扫描功能导入已安装的 Steam / Epic / GOG / 育碧 / Riot / WeGame / 战网 / Xbox 游戏。

游戏运行期间自动保护，切换到桌面或最小化不会失效。通过启动器启动的游戏（如英雄联盟）首次确认后会记住游戏本体，下次直接识别。启动器、更新器、崩溃上报和反作弊进程不会被识别为游戏。

游戏退出后按记录还原所有改动。Pavise 异常退出时，下次启动继续完成还原。

## 模式

| 模式 | 压制范围 |
|---|---|
| 智能 | 只压真在抢资源的后台，按热度逐级加码，闲置进程不碰。你正在用的程序和它的家族始终不动 |
| 专注 | 游戏之外全体降档省电，有窗口的也不例外，切出游戏后用的程序照降，只有白名单例外。真在抢资源的直接隔离到最高档，持续重负载的还会被装进作业对象硬限速 |
| 自定义 | 后台压制、核心、内存电源、系统环境、显卡逐项自选 |

两档都只对真占资源的进程动真格：智能档冷进程完全不碰，专注档冷进程只盖一层省电毯子。台架实测过全员隔离的旧做法是负优化——上百个空闲进程的零散唤醒被挤进两个核互相排队，最长帧翻 2.6 倍；只压忙的那几个，一毫秒就能拿到同样的收益。

任何模式下，反作弊、正在对局的游戏宿主、Windows 核心服务、网游加速器和其它登录账户都不会被压制。这条边界不受任何开关影响。游戏平台与启动器、网游加速器、反作弊、输入音频与外设链这四类自动豁免规则在白名单页可以直接查看。
## 逐游戏独立配置

游戏库里选中游戏点独立配置即可进入，每个游戏可以单独覆盖模式、后台压制、核心、内存电源、系统环境和显卡的全部 26 项。没覆盖的项跟随全局，改动立即保存，该游戏下一局生效。

- 生效值在对局激活的一瞬间定格，对局中改任何配置都是下一局生效，一局之内策略不会中途变化
- 当前的核心选择可以锁定给某个游戏，其它游戏不受影响
- 一套覆盖可以一键清回全局
- 概览页和托盘显示当前实际生效的模式，来自哪个游戏的独立配置会标注出来
- 驱动写入连续失败自动关闭对应开关时，该游戏的这条覆盖一并清除

游戏条目支持重命名，只改显示名称，识别不受影响。

## 功能

**进程和核心**

- 游戏进程获得高优先级、更高的磁盘 IO 和显卡调度优先级以及独立核心，后台按模式降级或迁移到其它核心
- CPU 分区适配混合架构、X3D 和多处理器组。6 核及以下不做核心切分
- 核心分配可以逐核手动划，预设有全核、关超线程、仅性能核和反选，改完要点应用才算数。多数人不需要动它，系统调度器默认就把游戏线程放 P 核
- 智能保帧：识别决定帧率的关键线程单独提升。台架实测 CPU 满载时 1% 最差帧改善 77%~96%
- 智能让位：CPU 持续吃满十秒且帧线程未能单独接管时，游戏本体暂回普通优先级，实测该状态下整进程高优先级恶化尾部帧。帧线程接管成功或 CPU 空出即恢复高优先级
- 对局自让位：Pavise 自己让出游戏核心并降低调度权重
- 后备提优：被内核反作弊挡住句柄的游戏改由系统在进程创建时给高优先级，下次启动生效
- 反作弊相容名单：被拒绝写入的游戏记进名单，注定失败的优先级和 IO 不再重试，显卡调度优先级和帧线程照常尝试。换版本自动失效，反作弊页可查看和清空

**显卡**

- 后台 GPU 让位：后台进程使用显卡时，同步降低其 GPU 调度优先级
- NVIDIA 逐游戏调优：电源最高性能、低延迟模式（开或超级）、Smooth Motion 驱动插帧、着色器缓存放开、DLSS 覆写（最新或指定 J、K 代）、按游戏开启 ReBAR。原值有快照，关闭即恢复
- AMD 逐游戏调优：Anti-Lag、AFMF 流畅帧、RSR 超分。RSR 开启前会说明它改的是整机渲染分辨率
- 显卡功耗墙：对局中拉到厂商允许的上限，退局按快照还原

**键鼠和中断**

- 关闭筛选键、粘滞键和切换键。微软对这几项的定义就是忽略短促击键，开着必然有延迟
- 禁止系统挂起键鼠设备，治的是空闲一会儿之后第一下操作发飘。只碰键鼠，不碰 U 盘和声卡
- 修复其它工具改动过的输入队列长度，关闭指针精度增强（系统那条鼠标加速曲线）
- 前台时间片三档自选：系统默认、前台加权、只报告。前台加权是老优化圈那个 0x26，依机型，台架上并非稳赢，选完请自己在同一场景对比；其它偏方值一律按异常报告
- 显卡中断亲和挪到靠近渲染线程的核心。USB 和硬盘控制器的中断亲和已在 1.8.1.0 下架，理由见下文

**内存和电源**

- 对局默认切到 Pavise 托管电源方案，首次对局自动创建，各项参数按本机处理器写入，名称带 PG 标签和本机签名；也可改选本机任意计划，Pavise 只负责切换不改其参数。设一次即不再定时轮询，避免与其它电源软件反复抢方案
- 托管方案按档位分两套。专注档写最低性能状态 100%、不停泊核心、能效偏好最偏性能、Boost 策略拉满；智能档保留降频余量，台式机上能效偏好同样写最偏性能并关掉插电时的占空比调制，笔记本给折中值
- 对局禁用处理器空闲：默认关，只在专注档且插电时生效。省掉核心从深度空闲唤醒的延迟，但**在相当一部分机器上是负优化**——禁掉空闲会连带压制睿频，频率反而上不去，实测过的笔记本就是这种情况。开启前会警告，开启时记录本机睿频基线，首局稳定后再测一次，明显低于基线就自动关掉并记住不再尝试。自动判定只是兜底，请自己开关各打一局对比
- MMCSS 多媒体调度：非多媒体工作的预留份额从 20% 调到 10%，Games 任务的调度类别和文件 IO 提到高档。游戏模式开启期间常驻，关掉或退出即还原
- Game DVR 后台录制在游戏模式开启期间关闭、退出 Pavise 才还原，因为它由系统在游戏启动那一刻读取，必须先于游戏就位才生效
- 电源计划、网络、通知在游戏结束后全部恢复

**系统环境**

需要重启、或者会留在机器上的改动集中在这一页，每一项都可还原：

- 硬件加速 GPU 调度（HAGS）。它对平均帧的影响在误差内，意义是驱动帧生成一类功能的前置条件，关着就用不了。不支持的机器置灰
- 关闭 VBS 虚拟化安全，开启前有风险确认
- 卸载 CPU 推测执行漏洞的软件缓解，回收每次内核态切换的固定开销。只有确实测到可回收开销的机器才放开
- 逐游戏关闭控制流保护 CFG，只改那一个缓解位，下次启动游戏生效
- 游戏模式守护、窗口化游戏优化、设备电源

**看得见的部分**

- 系统体检页：只读检查本机能力，每条结论标注依据等级。检出被第三方改坏的系统项可以就地一键修复，可查看显卡当前受功耗墙或温度墙限制的状态。中断那一行用内核 ETW 抓 DPC 和 ISR，直接点名头号来源
- 会话报告：游戏时长、压制的进程数量及其 CPU 占用、受功耗墙和温度墙限制的时间占比，以及游戏溢出到系统内存的共享显存峰值
- 游戏库支持强制接管，模拟器、云游戏这类识别不出来的，进程一起来就进对局
- 白名单独立成页，拖入即可，作用范围自动判断

纯本地工具，不安装服务、不上传数据、不注入游戏进程、不修改游戏内存和文件。每一步写入尽量读回核对，读不到预期值不计为成功。

## 内存清理

**这一类功能已全部移除。** 下面留着测量记录和逐条判词，说明为什么。

下表逐条测量了这类工具会用到的系统级命令，测试机 64 GB 内存，测量前可用 40344 MB、系统缓存 16154 MB：

| 命令 | 耗时 | 可用内存 | 系统缓存 |
|---|---|---|---|
| 清空所有进程工作集 | 1894.9 ms | +5191 MB | +3364 MB |
| 清待机列表（低优先级） | 13.3 ms | +144 MB | −47 MB |
| 清待机列表（全部） | 1380.6 ms | +382 MB | −18894 MB |
| 刷新修改页列表 | 8019.7 ms | +5845 MB | +251 MB |
| 合并物理内存页 | 6152.1 ms | +2121 MB | +531 MB |

清空整个待机列表丢掉 18894 MB 系统缓存，只换来 382 MB 可用内存。待机列表本来就计入可用内存，清空它是把缓存着的可用内存变成空着的可用内存，总量几乎不变，而缓存内容不再保留，紧接着的游戏加载要重新读盘。刷新修改页列表耗时 8 秒、合并物理内存页 6.2 秒，都不适合放在开局路径上。

**已移除：内存吃紧时清理低优先级待机内存**

这一项曾被当成"吸取教训后的保留版"，2026-08-20 实测证明它栽的是同一个坑，只是更隐蔽。

触发条件用的是可用内存比例，而可用内存本来就把待机页算在内——清理只是把页从待机链表挪到空闲链表，这个比例不会变，于是条件永远解除不了，45 秒冷却只是给无限重复定了个节拍。真实用户日志里 10 分钟触发 14 次，间隔精确 45 秒，从没停过。

更关键的是它几乎什么都没做：`MemoryPurgeLowPriorityStandbyList` 只清优先级 0 那一档，24GB 机器上那一档总共 1.4 MB，单次实际释放 0.0 至 0.1 MB，调用耗时 0.2 毫秒。省下的是内存管理器几百纳秒的页回收开销，对一帧的预算是噪声。

**已移除：对局稳定后回收后台工作集**

逐个调用 `SetProcessWorkingSetSize` 并不释放内存，只是把页从工作集赶到待机列表，其中的脏页还要先写进页面文件——这笔磁盘 IO 恰好落在对局中。而目标本身是已被压制的后台进程，正是内存管理器在有压力时首批自然裁剪的对象；它们没有被挂起，裁完立刻缺页读回，几秒后这轮工作就白做了，净效果是对局中多出一轮读写。

**已移除：ISLC 式清空整个待机列表**

`待机列表 ≥ 1 GB 且可用内存 ≤ 1 GB` 触发清整个待机列表，代价大于收益：1380 毫秒全系统阻塞加整个文件缓存丢弃，只换回 382 MB 可用内存。更关键的是没有冷却，5 秒一次检查——触发条件成立本就说明可用内存见底，清空后缓存被读盘重新填满，几秒内又会再次越线，低配机上会形成清空、读盘、再堆积的反复触发，比它想解决的周期性微卡更糟。当时以为只清低优先级那部分就能避开这两点，实测下来它同样是反复触发，而且释放量小到测不出——两个版本一起下架了。

相关论述见 Mark Russinovich《The Memory-Optimization Hoax》（Windows and .NET Magazine，2004 年 1 月）。

## 不做的事

流传的键鼠注册表优化项大多作用在零点几毫秒的量级上，而延迟的主要来源是渲染队列。这类项目 Pavise 只报告不修改，包括蓝牙鼠标和 125 Hz 回报率——体检页会把它们点出来，改不改由你自己决定。

MSI 模式、低延迟模式、后台硬限帧、游戏文件预热和按位置屏蔽 CPU 0/1 都实现过并已移除，原因分别是实测无效、有写坏设备的风险，以及语义理解错误——驱动中的后台限帧实际作用于失去焦点的应用，切出游戏后被限制的是游戏本身。

驱动级帧率上限（NVIDIA 与 AMD）在 1.8.0.3 下架：限帧交给游戏内设置或显卡控制面板更直接，驱动层再限一次容易与游戏自身的限帧和 VRR 打架；AMD 侧还要借道 Radeon Chill，与 Anti-Lag 互斥，等于用一个延迟优化换另一个。

1.8.1.0 收回三项：USB 与硬盘控制器的中断亲和，在性能核少的混合架构上会把中断投到低频能效核，造成高回报率鼠标空闲后第一下发飘；独立的对局核心解停泊覆盖，与托管电源方案里的停泊设置重复；逐游戏强制独显偏好，现代 Windows 本就默认给游戏挑独显。靠近渲染核的显卡中断亲和保留。

竞技档自动禁用处理器空闲同版收回，现在改成默认关闭的手动开关，开启后自己实测峰值频率，掉了就自动关掉。

极限模式和英雄联盟游戏专栏在 1.8.0.2 下架，专注即最高档。

移除的项目仍然知道自己写进去过什么、该怎么还原，但启动和版本更新不会自己动手——机器上已经生效的值只有你按下设置页的清除按钮时才会被改回去。

## 构建

使用 Windows 自带的 .NET Framework 编译器，不需要 Visual Studio，没有需要还原的包。

```cmd
build.cmd -b dev       rem 生成未混淆开发版 Pavise.exe
build.cmd -b prod      rem 生成基础混淆保护正式版 Pavise.exe
dev.cmd                rem 结束旧实例 → 开发构建 → 启动
```

源码构建没有数字签名，SmartScreen 会拦截提示。

## 运行和数据位置

双击 `Pavise.exe` 后进入托盘。调整其它进程需要管理员权限。开机启动通过计划任务实现。启动时向 GitHub 检查一次版本，不上传本机数据。

数据默认保存在 `%AppData%\Pavise`，包括目标配置、白名单和运行日志；界面和功能开关保存在注册表 `HKCU\Software\Pavise`。在程序旁放置空文件 `Pavise.portable` 后改为保存在程序目录。

设置页提供一键恢复。
