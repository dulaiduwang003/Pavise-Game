## 为什么是运行时资源编排器

Pavise 是一款开源、免费的 **Windows 游戏运行时资源编排器**。它以对局期间的智能后台压制为核心，协同游戏核心调度、关键线程、性能优先级与对局电源，为当前游戏编排资源。它的定位是运行时资源编排，而非传统的“一键优化”。

**Pavise 关注游戏运行时，资源如何被分配和使用。** 系统整洁程度只是运行环境的一部分，游戏自身的线程分布、核心选择、电源状态与资源竞争同样值得管理。通过逐游戏配置、执行核验与退局恢复，Pavise 让玩家掌握专业的运行时调度能力，充分发挥现有硬件的游戏性能。

我们希望，**让每一位玩家都能免费获得专业的 Windows 游戏运行时资源管理，享受更流畅、稳定的游戏体验。** 玩家不应为了用好自己已有的硬件，而不得不购买昂贵的优化软件。这也是 Pavise 坚持开源与免费的初衷：让实现可以被查阅，让技术能够被验证，让更好的游戏体验触手可及。

## 核心：对局时智能压制后台

**Pavise 的核心，是在对局时智能压制后台、减少资源争抢，让硬件原有的性能更充分地释放到游戏中。** 浏览器、启动器、更新任务与其他后台活动会与游戏共享 CPU、磁盘和 GPU 等资源。Pavise 根据使用场景与负载管理符合条件的后台，为游戏争取更充裕、稳定的运行空间。

开启守护并识别到游戏后，Pavise 会按你的设置：

- **让后台为游戏让路**：降低符合条件的后台 CPU、磁盘 I/O、内存与 GPU 调度优先级，并启用效率模式；配合核心调度，可将可管理的后台挪离游戏核心，减少干扰。
- **随场景调整压制范围**：智能场景结合前台状态与持续负载动态调整；竞技场景在对局期间持续压制，切出游戏后仍保留治理。
- **保护需要的程序**：游戏本体、必要依赖与手工白名单持续受保护；语音、直播等需要保留资源的软件可加入白名单。
- **退局恢复、执行可查**：按已记录的原值恢复本局临时改动，通过概览统计、动作日志与诊断日志查看实际压制和恢复情况。

CPU 调度、线程协同、电源与图形设置可与后台压制配合，把更多资源留给当前游戏；各模块均可按本机情况和逐游戏需求选择。

## 使用前请了解

**软件绝大部分功能仅在对局中生效，退局后自动恢复；不支持退局恢复的功能均已单独标注。** 长期项目按各自说明关闭或恢复，部分操作需要重启。文件删除和缓存清理不属于可恢复的设置改动。

**请勿与其他修改进程优先级或 CPU 亲和性的调度软件同时使用**，避免双方反复覆盖设置。

**安全软件提示与白名单：** Pavise 按所选功能执行进程调度、服务管理、电源与注册表设置等敏感操作，部分功能会调用 PowerShell，可能触发杀毒或安全软件的检测、拦截或报毒。请从官方渠道获取程序，核验来源后将 Pavise 程序加入所用安全软件的白名单，避免相关操作被拦截。**如对这些操作有安全顾虑，请先查阅本仓库公开源码，也可自行构建，再决定是否运行和授予管理员权限。**

优化收益取决于游戏、硬件、驱动与后台负载，可在固定场景中对照观察流畅度、卡顿与操作响应。

## 下载与开始使用

运行环境：**Windows 10 2004（19041）及以上、.NET Framework 4.7.2 或更高版本、管理员权限。** 各功能按本机能力提供。

| 下载方式 | 入口 |
| --- | --- |
| 官网完整 ZIP | [官网正式下载](https://pavise.club/changelog/#latest) |
| GitHub | [发布与下载](https://github.com/dulaiduwang003/Pavise-Game/releases/latest) |
| 夸克网盘 | [备用下载，请核对版本](https://pan.quark.cn/s/3c8c986b3ea4) |

1. 下载后放到固定目录；使用完整 ZIP 时，将随包文件一起解压。
2. 以管理员权限启动，添加实际游戏 EXE，检查白名单及逐游戏设置。
3. 选择所需功能或一键配置，确认智能／竞技场景与后台治理档位，开启守护后进入游戏。
4. 退局后查看恢复状态；需要排查时，导出该会话的日志。

升级前先退出游戏并正常退出旧版。软件内更新入口为 **关于 → 检查与更新**，更新保留个人数据。

## 从源码构建

在 Windows 上使用系统自带的 .NET Framework C# 编译器和 Windows PowerShell，无需安装 Visual Studio。

```bat
build.cmd -b prod
```

生成文件为 `build\Pavise.exe`，构建过程会核验实现和版本标识。

游戏库 → 深度调优 → 渲染线程调度的第一层开关独立负责开启／关闭，逐游戏默认关闭；开启前会提示效果因游戏和硬件而异、可能降低帧率或造成卡顿，需在相同场景自行对照。调整窗口提供六种方案，游戏优先排在第一位；尚未保存有效方案时，开启默认使用游戏优先，已有方案保持原选择。可按潜在收益场景选择，并一并设置清核与 GPU／磁盘资源优先级：

| 方案 | 潜在收益场景 |
| --- | --- |
| **游戏优先** | 游戏与其他程序争用 CPU，整个游戏和渲染线程都需要更靠前的调度位置。 |
| **渲染优先** | 渲染线程已准备运行，却因 CPU 争用而排队，影响画面响应。 |
| **渲染专核** | 渲染频繁换核造成缓存重建开销，影响帧时间稳定性。 |
| **多核协同** | 多个关键任务挤在同核，同时其他繁忙任务需要并行空间。 |
| **依赖协同** | 渲染在等待关联任务完成，单独提优渲染无法缩短这段等待。 |
| **专核强化** | 固定渲染核心后仍受普通线程竞争影响，画面响应对调度等待敏感。 |

这些是可能受益的瓶颈场景，不代表已检测到该问题，也不保证性能提升。方案和资源优先级在同一窗口保存，下局生效，不改变启停状态；关闭立即撤销写入资格并按归属恢复。显式开启时，当前目标及方案尚无已开启的识别阶段才可当局开始；同一阶段已关闭则保留已耗预算，下局生效。已保存的旧对照规则按关闭处理，重新选择正式方案后仍需明确打开第一层开关，不会静默启用。各方案保留游戏原有更高优先级，沿用有界角色识别、实际设置核验、持续纠偏和恢复记录；身份或范围未知时暂停相关写入。实际帧时间收益需通过固定场景对照判断，不能由设置读回推定。资源优先级仍须渲染线程调度开启，只面向 GPU 与磁盘资源竞争；不再设置或恢复游戏内存页优先级；调度诊断仍可只读记录原始状态。

游戏优先把三项配合使用：游戏进程设为高优先级（游戏原本为实时优先级时保留原类别），已确认的渲染线程固定到自动选出的核心，并提高该线程的优先级。整进程 CPU 高优先级仅由本方案接管，与 GPU／磁盘资源开关独立；其余五种方案不主动提高游戏进程的 CPU 优先级类别。进程优先级入局后即设置，线程部分在识别到渲染线程后生效；选不出核心时本局不固定，其余照常。拒绝写入的受保护游戏只应用可生效的部分。进程原优先级单独记录，关闭、退局或换成其他方案时恢复，其他程序的后续改动保留。CPU 满载时，语音、直播、录屏等其他程序可能变慢。

专核强化是渲染专核之外更积极的对照方案，只加强已确认的稳定呈现线程，不改变游戏进程优先级。必须核验实际拓扑、合法范围与绑定；无法选核或绑定时不以未绑核状态提优。Pavise 控制线程还须可在目标核外运行。启用清核时，须另外确认最近线程快照的完整覆盖。覆盖不足、清核维护失败或核验条件失效时，停止新增提优并按归属撤回本方优先级增量；核验恢复后沿用原会话与剩余预算继续。首次提优预算耗尽后停止本阶段新增，先恢复优先级再解除绑定。游戏进程已设为高优先级、实时优先级，或目标线程采用特殊优先级时不新增接管。清核为独立选项，只约束已覆盖的游戏线程；系统任务仍可能使用该核，不能视为系统级独占。

依赖协同照顾与画面呈现有关的少量稳定关联任务，保留原有核心范围，不固定核心，也不使用清核。首次接管须由独立观察反复确认同一呈现身份和关联成员，CPU 占用高本身不构成提优依据。该方案不按 CPU 品牌、大小核、超线程、核数或处理器组限制选用；身份或优先级权限无法核验时不写入，小组不能完整接管时整体撤回。确认后只维护已接管线程的优先级；关闭、退局及角色退出按归属恢复。退出后的有限复核须保留同一呈现身份，并用新证据重新确认成员资格；依赖线索不等于已证明帧关键路径，也不代表覆盖所有负载线程。

角色发现次数按每个受管游戏会话及规则阶段计算：游戏优先、渲染优先、渲染专核及专核强化最多 2 次完整采集，多核协同与依赖协同最多 3 次，每次约 3.2 秒；同一游戏进程内连续比赛不会自动补充次数。关键角色确认退出后，先撤销旧写入资格并按归属恢复原计划，包括其他线程的清核限制。恢复结清且原阶段仍有采集额度时，最多复核一次替代角色，重新核验身份和原值；复核已用过或额度耗尽时仍恢复旧计划，停止新增接管。恢复未结清时不开始新观察或新接管，首次接管、新线程接纳和失败预算均不重填；存活线程职责变化不会自动触发重选。

## 后台压制：场景与强度

**使用场景与压制强度分开设置。** 智能／竞技决定何时、以什么范围管理后台；界面中的“后台治理”决定压制强度。游戏、手工白名单和必要依赖持续受保护。

| 场景 | 行为 |
| --- | --- |
| **智能** | 游戏在前台时按负载调整治理范围，持续高负载时扩大范围，负载回落后收回；切出游戏释放后台治理，对局电源与亲和性继续保留。 |
| **竞技** | 对局期间持续治理，切出游戏保留治理与亲和性；普通软件切到前台不会因此自动豁免。 |

| 后台治理档位 | 行为 |
| --- | --- |
| **关闭** | 关闭后台治理，包括内置微软后台名单。 |
| **正常** | 降低符合条件的后台资源优先级并启用效率模式；内置名单中的每个目标使用 Windows Job 最低非零 CPU 配额 0.01%（CpuRate=1）及最多两个后台物理核心。 |
| **激进** | 在正常档基础上限制后台线程临时提优；内置目标同样使用最低非零 CPU 配额 0.01%，核心范围收紧为最多一个后台物理核心，进一步降低 CPU 与 I/O 优先级。 |

反作弊专项中，已成功接管的资源字段和亲和性持续核验并纠正回写，不因累计冲突次数永久放弃；失败最多退避 30 秒并限频记录，身份、原值或合法范围未知时暂停。首次接管、新线程与恢复仍有界；关闭、切档和退局先撤销旧写入资格，再按归属恢复原值，保留之后的外部修改。

内置名单包含 DiagTrack、DPS、WdiServiceHost、WdiSystemHost、diagsvc、WSearch 及已核实的索引工作进程、小组件和所属 WebView2，低占用时也纳管，沿用现有治理档位。系统预设白名单不豁免这些目标，用户手工白名单与家族保护仍然有效。共享服务宿主仅在其运行服务全部属于名单时纳管；未运行的服务不会为此启动，退局恢复原值。

清核会在确认普通游戏线程退出、并核验恢复账本更新后回收该线程记录，让后续新线程继续使用空出的容量。存活、身份未知或尚需恢复的记录仍保留，回收不会补充失败重试次数；当前可维护容量和新线程扫描间隔仍可能造成覆盖缺口。

**核心范围需点击保存。** 选核和隔离先保留为草案，离开页面或切换游戏不会自动保存。启停由深度调优中的独立开关管理。刷新、切换主题和缩放保留草案，保存失败保留选择；“恢复已保存”可重新载入配置。全选且不隔离时不额外限制游戏核心范围，省去相应的 Job、守护和周期核验。保留游戏已有范围并继续处理恢复待办，渲染调度和清核仍按实际允许范围核验。

**自动选核遵守游戏核心范围。** 独立核与清核只在游戏核心范围内选核，并避开其他功能预留的物理核；未开启游戏核心范围时不额外收紧可选范围，仍尊重游戏原有的进程范围。普通策略保存与核心范围调整下局生效；显式开启按上述当前目标及策略的识别阶段判断，关闭立即停止纠正并按归属恢复本方设置。线程固定不等于整核独占，系统中断和受保护进程仍受 Windows 管理。

## 配置预设与电源

作者同款／极限配置用于批量设置功能，与智能／竞技场景分别选择。两套预设的 **CPU 空闲策略均为“跟随原策略”，前台时间片均为“恢复原配置”**；更新软件保留已有选择，重新应用预设时才按新定义设置。

预设中的 VBS、CPU 软件缓解等长期项目会改变相应系统防护，请按功能说明和重启提示处理。

智能与竞技共用电源参数。软件托管时，笔记本沿用旧策略，台式机按 CPU 匹配预置；高性能模板缺失时，可核验后复制原计划作为候选。识别到支持名单中的掌机时，由系统和厂商软件管理电源。

对局持有电源计划期间，守护持续核验活动计划和托管参数，并写回外部改动；不会因外部反复修改而自动改成“不切换”。核验和写回串行执行，反复冲突时反应间隔放慢至最多 15 秒，日志限频。首次接管、计划创建、写入失败、监视登记失败和退局恢复仍有明确次数上限；退局恢复保留外部后写值。旧版曾自动改成“不切换”的设置，需重新选择电源计划。

## 软件架构

## 游戏优化执行流程

识别游戏 → 建立会话与配置快照 → 按条件执行 → 核验并记录 → 退局恢复。每项功能按自身开关与能力条件运行。

首次采集、接管、写入失败和恢复重试均有执行上限。已接管字段的运行期纠偏及对局电源计划守护按各自规则持续核验，身份或合法范围未知时暂停相关写入。恢复预算耗尽后停止主动尝试，保留恢复记录与持有资源，日志显示实际恢复状态。
